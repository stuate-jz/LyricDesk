# 发布页：怎么用

先说结论：

- **发布页 = 你 Gitee 仓库的首页**（把这个文件夹里的 `README.md` 传上去，Gitee 会自动渲染成一个网页）
- **下载 = 仓库的 Releases 页面**（把 zip / 安装程序当附件传上去）
- **更新源 = `gitee:你的用户名/仓库名`**（填进程序的「设置更新源…」，以后它自己检查新版本）

这三样都不需要买服务器、不需要备案，Gitee 国内直连，朋友点开就能下。

---

## 一、准备两个文件（已生成，只需要换名字）

这个文件夹里现在有：

| 文件 | 用途 | 传到哪 |
| --- | --- | --- |
| `README.md` | **发布页本体**，仓库首页会渲染它 | 仓库根目录 |
| `update.json` | 版本信息，程序检查更新时读它 | 仓库根目录 |
| `screenshots/` | 页面里的三张截图 | 仓库根目录（整个文件夹） |
| `index.html` | 备用：想要独立网址时的网页版 | 见第五节 |

**换成你自己的地址**：在项目文件夹里跑一行命令（把 `你的用户名` 换成 Gitee 用户名）：

```powershell
python dev\make_release_files.py 你的用户名/LyricDesk
```

它会重新生成 `README.md` 和 `update.json`，里面所有链接、更新源都会自动填好。
（当然也可以手动把文件里的 `你的用户名` 全部替换掉。）

---

## 二、建仓库并上传发布页

1. 打开 <https://gitee.com> 登录 → 右上角 **+** → **新建仓库**
2. 仓库名称填 `LyricDesk`（路径会自动变成 `lyricdesk`），选 **开源 / 公开** → **创建**
3. 进去后点 **上传文件**（或者页面上「克隆/下载」旁边的 `+` → 上传文件）
4. 把 `README.md`、`update.json` 拖进去；`screenshots` 文件夹也一起拖进去
5. 填个提交信息（随便写，比如「发布页」）→ **提交**

刷新仓库首页，你就能看到一张做好的发布页了。地址就是：

```
https://gitee.com/你的用户名/LyricDesk
```

> Gitee 有时要求先完成手机号绑定 / 实名认证才能创建公开仓库，按页面提示走一遍即可。

---

## 三、发一个版本（上传下载文件）

1. 仓库页面找 **发行版 / Releases** → **创建发行版**
2. 标签名称：`v1.5.2`（以后每发一版就换成 v1.5.3、v1.6.0…）
3. 标题：`桌面歌词 v1.5.2`
4. 说明：把 `update.json` 里 `notes` 的那几行复制进去
5. **上传附件**：把下面两个文件拖进去
   - `桌面歌词-v1.5.2-便携版.zip`（必传，朋友主要下这个）
   - `桌面歌词-安装程序-v1.5.2.exe`（可选）
6. 点 **发布**

发布完，下载页就有了：

```
https://gitee.com/你的用户名/LyricDesk/releases
```

**想让「打开下载页」按钮一键直接下载？** 在 Releases 页面里右键那个 zip 的下载
链接 → 复制链接地址，粘贴到 `update.json` 的 `url` 字段，重新上传这个文件即可。
不换也没关系，`url` 现在指向 Releases 页面，用户多点一下而已。

---

## 四、让程序会检查更新

桌面歌词 → 右键菜单 → **设置更新源…** → 填：

```
gitee:你的用户名/LyricDesk
```

点确定。之后：

- 每次启动程序会**静默检查一次**（24 小时内只查一次），有新版本才发托盘通知
- 想立刻查就点 **检查更新…**

想连这一步都省掉（朋友拿到手就能自动更新），把你的 `用户名/仓库名` 告诉我，
我可以把它写进程序里当默认更新源，再重新打一个包。

---

## 五、（可选）想要一个独立网址，而不是仓库首页

`index.html` 是我另外做的网页版，比仓库首页好看一些，需要能托管静态网页的地方：

**路线 1：Gitee Pages**
仓库 → **服务** → **Gitee Pages** → 部署分支选 `master` 或 `main`、目录 `/` → 启动。
得到 `https://你的用户名.gitee.io/lyricdesk/`。

> Gitee Pages 偶尔调整政策、也可能要求实名认证；如果找不到入口或提示不能开，
> 直接用仓库首页当发布页就行，功能上没有区别。每次改完文件要在 Pages 页面点一次「更新部署」。

**路线 2：自己的域名 / 云存储**
把 `index.html`、`update.json`、截图一起传到任意静态托管（腾讯云 COS、阿里云 OSS、
自己的服务器…），把文件权限设为公有读。更新源填 `https://你的域名/update.json`。

> 注意：Cloudflare Pages 这类境外托管在当前网络下可能打不开（我实测 `pages.dev` 连不上），
> 发给国内朋友的话，优先 Gitee。

## 六、以后每发一版，固定四步

1. 改 `packaging\update.json` 里的 `version` / `date` / `notes`
2. 跑 `python dev\bump_version.py 1.5.3` 把版本号同步到所有地方
3. 重新打包（PyInstaller + Inno Setup）
4. 跑 `python dev\make_release_files.py 你的用户名/LyricDesk`，
   把新的 `README.md` / `update.json` 传到仓库，并把新 zip 传到 Releases

第 2、3 步跟我说一声「发个新版」我就帮你跑完，你只管第 1 步的文字和第 4 步的上传。

---

## 七、容易踩的坑

- **下载链接不能用网盘分享页**（微云那种），要用直链：Gitee/GitHub 的 Release 附件、
  或者云存储的公有读链接。
- **Gitee 单个附件上限 100 MB**，我们现在 43 MB，够用好几版；GitHub Release 上限 2 GB。
- **更新源里的版本号必须比当前大**，程序才会提示更新（1.5.2 → 1.5.3 → 1.6.0）。
- **改完 `update.json` 记得重新上传**，并在浏览器打开 `https://gitee.com/你的用户名/LyricDesk/raw/master/update.json`
  确认内容已经更新（Gitee 有缓存，通常等一两分钟）。
- 只发压缩包给朋友时，可以把 `update.json` 放在 `LyricDesk.exe` **同一个文件夹**，
  程序会直接拿它当更新源（这样对方点「检查更新…」不会报错）。
